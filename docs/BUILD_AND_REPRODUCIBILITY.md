# Build and reproducibility boundary

The provided source ZIP and release ZIP contained the same 284,345-byte BPS, SHA-256 `0d90bce872e7383497b90ef6051bf197260eb2ddc1ea4dd9c2d63c36c0e40504`. Its `BPS1` header declares 8,388,608-byte source and target, and its stored patch CRC32 `AF1202F6` matches a fresh CRC32 calculation. The BPS metadata and source/target CRC32 (`2460B45A` and `A502A8D0`) were read from the patch; the clean-ROM SHA-256 and output SHA-256 are **documented expectations**, not recalculated from ROMs in this packaging run.

The historical `validation/S459/SOURCE_REBUILD.json` and `BPS_ROUNDTRIP.json` record a byte-exact source/BPS output match before archive sanitization. This packaging run had no clean Japanese ROM, so rebuilding the new sanitized source chain, applying the patch, and comparing outputs are **NOT_RUN**. The S459 BPS itself was not regenerated or modified.

The source chain remains `build.py` → S459 → S458 → S457 → sanitized nested S456→older builders. The builder requires the user-provided clean ROM at SHA-256 `62f3886d3bae02105e56677ae7f5efe77ff7cb47036d2955ca46ea4a3f712921` and checks the final expected SHA-256 `c79079537ea5f66cf74f94d48afc3da14dd9db1f8458156d337f5e0107c111dd`. Use `python3 build.py clean-jp.wsc build/Riviera-English-RC3.wsc` or `BUILD.bat` on Windows; run `python3 apply_patch.py clean-jp.wsc build/Riviera-BPS.wsc` separately and compare `sha256sum` (or `shasum -a 256`) and bytes. These are distinct operations. Python 3.9+ is recommended by the existing builder; Linux reports used Python 3.12 and Mesen 2.1.1. Windows/macOS were not run here.

The original S456 archive had 154,937,827 bytes and SHA-256 `e62c5cf94102fb8880a3b627c3e0d8974c4d7c212aafdcfac4ecb71f6b42444e`. After removing 13 `.mss` savestates and 210 `.pyc` entries across 17 ZIP levels, it has 145,694,256 bytes and SHA-256 `1e2f381ef0186d5763dc762047db1978f8eff520351f3cdd70db5eb3d78db9b7`. Four chunks preserve the original path and order, but their old hash is superseded. `source/Riviera_S457_FULL_SOURCE/source/RELEASE.json` and nested `upstream_sha256` references now identify the sanitized bytes. Old historical manifests may still contain the old file hashes; consult the organization manifest for the rewritten chain.

Source build status after this change: **NOT_RUN (clean ROM unavailable)**. Source-chain integrity and BPS identity are verified independently. A publication gate requiring a newly demonstrated source/BPS byte match must be completed by a maintainer holding the clean ROM.
