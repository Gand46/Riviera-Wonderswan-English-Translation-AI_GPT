The reading is supported by linked primary game credits, not a name dictionary or an unrelated homonym:

The identity linkage is an inference from these matching credits and staff group; the Latin spelling itself is directly visible in the original screenshot. The Japanese Treasure Wars 2 evidence is primary ROM data, not a claim that its credits were reached in gameplay.

## Bounded integration

- Resource: `CREDIT-7A3D29`, credit page 9 (counter 10), 96×96 pixels, destination WRAM `0x5B60..0x6D60`.
- Existing compressed allocation: `0x7FF4EA..0x7FF9B1`, 1,223 bytes.
- Full name would require 104 pixels on one line. It is wrapped as `Nobuyuki` / `Hashimoto`, using the existing native glyphs at `0x5534BC`, unchanged spacing and 10-pixel line pitch. Eight lines fit the existing animation envelope, matching the established wrapped-name method used on other credit pages.
- The six neighboring names retain their exact glyph pixels and wording. Their vertical placement changes where required by the extra line.
- A shortest-stream encoder uses the **existing** zero-run/literal RLE grammar. The new stream is 1,180 bytes, with 43 padding bytes inside the old allocation. Decompressed data is exact. No new runtime decoder is installed.
- Font, hooks, decoder, animation tables, duration, other credit pages, text selectors, game code, stats and save code remain unchanged.
- Actual diff: **1,128 bytes**, all inside the graphic allocation or checksum. Unexpected changed offsets: **0**.
